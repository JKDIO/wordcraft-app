### C. 가족 기능 — 전수 감사 결과와 봉합 (★P0 3건★)
감사에서 **"완료"로 알려져 있던 다가구 기능에 실사용 전 미발견 결함**이 나왔다.
- **P0-1. 세션 만료 = 로그아웃 (익명 계정 무한 증식의 진짜 원인)**
  - `getAuthUser()`가 401(액세스 토큰 만료)에서 **리프레시를 시도하지 않고 null**을 돌려줬다. App은 이를 "세션 없음"으로 보고 **새 익명 계정을 생성**했다.
  - 실측: auth.users **35명 중 익명 33명**, 예한이 learner에 device 멤버십 **17행**(7/24~8/12, 실기기는 1대). 액세스 토큰 수명 1시간 → 한 시간 뒤 앱을 열 때마다 새 계정.
  - 수정: `ensureFreshSession()`(만료 임박 시 선제 갱신) + `getAuthUser()` 실패 시 **리프레시 1회 재시도 후에만** 로그아웃 판정 + `refreshSession()`은 **400/401/403일 때만** 세션 폐기(네트워크 끊김·5xx로 오프라인 로그아웃 금지) + 신규 `ensureAnonSession()`(살아있는 세션 재사용).
- **P0-2. 보호자 기기가 아이 기기로 강등될 수 있었다**
  - 보호자 구글 세션이 만료되면 role이 `legacy`로 떨어지고, 로컬에 learnerId가 있으면 **익명 로그인 + 그 아이에 device 바인딩**까지 실행됐다.
  - 수정: 기기 정체를 세션과 분리해 기억(`wordcraft_auth_kind_v1`). 보호자 기기는 세션이 끊겨도 강등하지 않고 **가족 화면의 재로그인**으로 보낸다. FamilyDashboard에 **"구글로 다시 로그인"** 화면 신설(종전엔 쓸모없는 가족코드 입력 폼만 떴다).
- **P0-3. 아이 딥링크 재방문마다 새 계정** — `Connect`의 원터치 시작이 조건 없이 `signInAnonymously()`를 호출했다. → `ensureAnonSession()`으로 교체.
- **P1. 보호자가 실제로 연결했는지 볼 방법이 없었다** — 그래서 **진영이네가 한 번도 로그인하지 않은 것을 아무도 몰랐다**(guardians=0, 아이 찬영·호영 XP 0). 슈퍼 관리실에 **보호자 연결 현황**(관계·가입일·마스킹 이메일·아이 기기 수) 표시 + 미연결이면 경고 배너. 소유자용 **가족 정보 수정**(가족명·부모명) 추가 — 예한이네 `parent_name`이 null인 채 앱에서 고칠 방법이 없었다.

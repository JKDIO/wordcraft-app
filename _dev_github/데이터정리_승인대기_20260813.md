## ② 승인 시 실행할 SQL — 고아 익명 계정 정리
```sql
-- 안전장치: 학습 기록이 조금이라도 연결된 계정은 절대 건드리지 않는다.
-- 판정 기준: 익명 + (최근 3일 내 생성된 멤버십 없음) + (그 계정이 유일한 device 바인딩이 아닌 learner)
with keep as (
  -- 최근 3일 내 활동한 익명 계정 = 살아있는 기기로 간주하고 보존
  select distinct user_id from memberships where created_at > now() - interval '3 days'
),
victims as (
  select u.id from auth.users u
  where u.is_anonymous
    and u.id not in (select user_id from keep where user_id is not null)
)
-- 1단계: 멤버십만 정리 (learner·학습기록은 그대로 — learner_id는 memberships가 아니라 learners에 산다)
delete from memberships m using victims v where m.user_id = v.id;

-- 2단계: 계정 삭제 (Supabase 대시보드 Authentication → Users 에서 하거나 admin API 사용)
-- ⚠️ auth.users 직접 DELETE는 권장하지 않음. 대시보드/Admin API 경로를 쓸 것.
```

**실행 전 반드시 확인할 것**
1. 예한이 폰이 최근 3일 안에 앱을 열었는지 — 안 열었다면 `interval '3 days'`를 더 길게 잡아야 예한이 기기 바인딩이 살아남습니다.
2. 삭제 후 예한이 폰에서 앱을 열어 정상 로드되는지(L23 봉합 덕분에 바인딩이 끊겨도 자동 재바인딩됩니다).

## ③ 굳이 안 해도 되는 것
- 익명 계정 34개는 **기능상 아무 문제도 일으키지 않습니다.** Supabase 무료 티어 한도에 여유가 있고, L23 봉합으로 **더 이상 늘지 않습니다**(배포 후 신규 0건 확인).
- 즉 이 정리는 위생 작업이지 긴급 작업이 아닙니다. 급하지 않으면 미뤄도 됩니다.

# WordCraft 진행상황 — 2026-08-14 (v1.4.30: 뱃지 도감 기본 접힘 + '열기 ▼' 버튼 강조)

## 지시

> "앞으로 예한이 앱에서 뱃지는 모두 접힌 상태가 디폴트가 되도록 해 주고, 또한 열리는 버튼을 강조하여 바로 인지할 수 있도록 수정해줘. 모든 수정 내용은 모든 곳에 기록해줘."

## 1. 무엇이 문제였나

v1.4.27에서 뱃지가 59종이 되며 카테고리 접기/펴기를 도입했고, 그때 기본값은 **"하나라도 딴 카테고리는 펼치고, 0개인 곳은 접는다"** 였다. 의도는 "아이가 자기가 이룬 것을 먼저 보게 하자"였다.

v1.4.28에서 뱃지가 **71종**이 되면서 이 규칙이 뒤집혔다. 예한이는 이미 11개 분야 중 8개에서 뱃지를 땄기 때문에 **내 정보를 열면 8개 카테고리가 통째로 펼쳐진 채** 시작한다. 카드 40여 장이 세로로 깔리고, 화면을 열자마자 하는 첫 행동이 "스크롤"이 된다. ⚔️ 룬 장비창(v1.4.28)이 "지금 내가 얼마나 강해졌는가"를 한 그림으로 답하도록 만들어졌는데, 정작 그 아래가 아이를 파묻고 있었다.

여는 어포던스도 약했다. 카테고리 머리글 오른쪽 끝의 **11px · 불투명도 0.55짜리 `▼` 하나**가 전부였다. 초6이 어두운 배경에서 이걸 "누르는 것"으로 읽어낼 근거가 없다.

## 2. 무엇을 바꿨나 (`src/screens/Profile.tsx`)

| | 이전 (v1.4.27~29) | 이후 (v1.4.30) |
|---|---|---|
| 기본 상태 | 획득 ≥1인 카테고리는 펼침 | **11개 전부 접힘** |
| 상태 저장 | `Record \| null` + `defaultOpen()` 계산 | `Record` 하나. 명시적으로 연 것만 `true` |
| 여는 표시 | `▼` 11px · opacity .55 | **금색 채움 '열기 ▼' 알약** 56×26 · weight 900 · 금색 글로우 링 |
| 열린 표시 | `▲` 같은 크기 | 테두리만 있는 '닫기 ▲' — 대비가 뒤집혀 **열린 줄이 어디인지도** 보인다 |
| 전체 토글 | 무테 텍스트 `전체 펼치기` | **📂 칩 버튼** |
| 안내 문구 | `🔍 물음표 뱃지를 탭하면 획득 조건이 보여!` | `👇 분야를 눌러서 열어봐! 물음표엔 조건이 숨어 있어` |
| 검사 접점 | 없음 (이모지 문자열로 추정) | `data-wc-group` · `data-wc-open` 속성 |

**교육적 근거**: 접힘 기본값은 인지 부하를 낮추고(정보 계층화), 아이가 **직접 열어 보는 행동**을 만든다 — 수동적 스크롤보다 능동적 선택이 기억에 남는다. 장비창 슬롯을 누르면 그 분야만 열리는 기존 동선(v1.4.28)도 이제야 제 값을 한다. 접힌 목록이 그 자체로 "아직 안 본 상자"가 되기 때문이다.

**관제실(아빠 앱)은 바꾸지 않았다.** 아빠 화면의 뱃지 도감은 훑어보는 것이 목적이라 옛 규칙이 맞다. **두 앱의 UI 규칙이 갈라진 첫 사례**이므로 RELEASE_LOG·START_HERE에 명시했다.

`app.css`는 손대지 않았다 — 새 클래스 없이 인라인 스타일로만 처리했다(이월 과제인 app.css 크기 불일치를 이번 릴리스에서 건드리지 않기 위해). 그래서 **배포물은 `main.js` + `version.json` 2종**이다.

## 3. 검사 (badge_ui_smoke.mjs 보강)

판정 3개를 새로 넣었다.

1. 11개 카테고리가 **전부 닫힘** — `data-wc-open="0"` + `▼` + '열기' 라벨
2. 진입 시 `.badge-card` 개수 **0**
3. '열기' 알약이 **실제로 칠해져 있고**(`backgroundColor`가 투명이 아님) **56×26px 이상** — "강조했다"를 말이 아니라 계산된 스타일로 판정

**결함을 되살려 잡히는 것까지 확인했다(L27④).** 기본값을 옛 규칙으로 되돌려 빌드하니 즉시 `❌ 실패`, 원복 후 `✅ 통과`.

- **예한이 실기기(갤럭시 A24) 미확인.** ① 알약이 손가락으로 정확히 눌리는가(56×26px + 머리글 전체가 버튼이라 타깃은 충분해 보이지만 실측 아님) ② **접힌 목록이 아이에게 "볼 게 없다"로 읽히지는 않는가** — 이게 가장 큰 미검증 리스크다. 반대 시나리오: 아이가 아예 열어 보지 않게 되어 뱃지 도감 체류가 줄 수 있다. 관제실 데이터로는 잡히지 않으니 **직접 물어봐야 한다.**

## 6. 함께 바로잡은 것 — 낡은 로컬 사본 (L32 제정)

노트북 배포 저장소 루트의 `content.json`이 **v1.4.23판(1,596,256B)에서 멈춰 있었다.** 라이브·GitHub·소스 tgz는 모두 v1.4.26판(1,886,568B, SHA `f5b4b927…`)으로 정상이었다. 즉 **로컬 폴더만 몇 릴리스 뒤처져 있었고 아무 에러도 없었다.** 이 사본을 그대로 다시 올렸다면 월드 7~10 콘텐츠가 통째로 되돌아갔을 것이다. 라이브와 동일한 파일로 덮었다.

→ **L32**: 배포 저장소의 로컬 사본도 진실이 아니다. 진실 3종은 **버전 문자열**만 지켜 준다 — **내용물은 SHA256으로만 지켜진다.** 세션 시작 시 라이브 배포물의 해시를 브라우저에서 직접 계산해 대조할 것. (크기 비교는 오판을 부른다 — 한글 때문에 UTF-8 바이트 수와 JS 문자열 길이가 다르다. 이번에 실제로 한 번 오판했다.)

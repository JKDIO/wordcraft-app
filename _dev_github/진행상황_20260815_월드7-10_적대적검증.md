## 1. 방법 — 왜 이렇게 했나

프로젝트 헌법의 "고친 사람 ≠ 검수한 사람"을 라운드마다 지켰다. 매 라운드 검수자는 **처음 보는 눈**이다.

```
1차 감사(독립 12 + 교차 1)  → 200건 ─┐
2차 수정(12 에이전트)        → 469곳  │  ★수정한 사람은 다음 라운드에 참여하지 않는다★
3차 재검증(독립 8)           →  71건 ─┤
4차 수정(6 에이전트)         → 199곳  │
5차 최종검증(독립 2)         →  19건 ─┤
6차 마무리 수정              → 129곳 ─┘
```

라운드마다 **수정 브리프에 "먼저 반박하라"를 넣었다.** 검수자는 틀릴 수 있고, 틀린 지적을 그대로 고치면
멀쩡한 콘텐츠가 망가진다. 실제로 102건이 근거와 함께 기각됐다(취향 문제, 문맥 오독, 대안이 더 나쁜 경우).

### 라운드가 필요했던 이유 — 수치로

| 라운드 | 발견 | P0 | 성격 |
|---|---|---|---|
| 1차 | 200 | 34 | 원래 있던 결함 |
| 2차 | 71 | 0 | **32건이 "고치다 만 것", 23건이 "고치다 새로 생긴 것"** |
| 3차 | 19 | 6 | 2차 수정의 부작용(문구가 너무 길어짐 등) |

**한 번 고치고 끝냈다면 71건이 그대로 남았다.** 특히 2차에서 나온 "수정이 새 결함"이 23건이라는 사실이
이 프로젝트에서 재검증 라운드를 생략하면 안 되는 이유의 실측 근거다.

### 반복 패턴 세 가지

1. **모듈 안 자기모순** — 한 곳에서 규칙을 가르치고 다른 곳에서 반대로 말한다(9건). 사람은 문항을 하나씩 만들지, 모듈 전체를 동시에 보지 않는다.
2. **공짜 문항** — 보기 괄호에 정답 한국어 뜻이 그대로 적혀 있거나("(기운 내!)"), 질문 번호가 곧 정답 순서(1-2-3-4). 인출 연습 효과가 0이 된다(7건).
3. **콤마 하나로 갈리는 오답** — 초6에게 공정한 시험이 아니고, 그 콤마 규칙을 가르친 적도 없다(8건).

## 3. 앱 수정 (v1.4.35 → v1.4.36)

### `alt_answers` — 맞는 답을 틀렸다고 하지 않는다

```ts
// OrderGame.tsx
const norm = (s: string) => s.trim().toLowerCase().replace(/[.!]+$/, '').replace(/\s+/g, ' ')
const accept = [item.answer, ...(item.alt_answers ?? [])].map(norm)
const ok = accept.includes(norm(built))
```

- 대소문자와 **끝** 마침표는 무시하고, **콤마는 구별한다**(뜻이 바뀌므로).
- `SummonExercise`도 같은 규칙.
- **어순 자체가 학습 목표인 문항에는 넣지 않았다** — 그건 오답이 맞다. 그런 문항은 `prompt_ko`에 힌트를 넣어 의도를 알렸다.
- 적용 결과 31개 문항. 전부 **토큰 순열로 실제 조립 가능한지 기계 검증**을 통과했다(조립 불가능한 대안 정답은 죽은 코드이자 거짓말이다).

### content.json 캐시 무효화 (L38 재발 방지)

`fetch('/content.json')` → **`fetch('/content.json?v=' + APP_VERSION)`**.
그림 자산에서 이미 겪은 사고다. 내용을 고쳐도 CDN·WebView가 옛 것을 계속 쓰면 **고친 것이 아니다.**

## 4. 배포 방법 — content.json 정밀 패치 CI (신설)

`content.json`은 1.9MB다. 모델 문맥을 통과시킬 수 없다(L7·L34). 그래서:

```
패치 797개 → JSON 최소화(119KB) → gzip+base64(45KB) → _ci/content_ops.b64 커밋
   → GitHub Actions `wc-content-apply` 가 적용 → content.json 커밋 → Vercel 자동배포
```

**안전장치 3중** — 하나라도 어긋나면 아무것도 커밋하지 않는다:

| 검사 | 뜻 |
|---|---|
| `before` 정규화 sha256 | 저장소의 content.json이 **내가 검증한 그 파일**인가 |
| 경로 존재 검사 | 오타 난 경로가 조용히 무시되지 않는가 |
| `after` 정규화 sha256 | 적용 결과가 **내가 로컬에서 검증한 결과와 완전히 같은가** |

정규화 해시 = `sha256(json.dumps(data, sort_keys=True, ensure_ascii=False, separators=(',',':')))`
→ 파일 포맷(들여쓰기)과 무관하게 **내용만** 비교한다.

실제 결과: `ops=797 · before=905670c8… · after=3fd79b3d… · bytes=1905119` — 두 관문 모두 통과.

## v6.2 (2026-08-29) — 진짜 원인 규명 + 재수정 + 재검증 — 완료

### 근본 원인 (Playwright로 격리 테스트해 확인)
`mask-image`는 이 요소가 `.knight-stage`(`perspective:600px`)·`.knight-figure`(`transform-style:preserve-3d`)로 만들어지는 **3D 렌더링 컨텍스트 안에 있으면 Chromium이 사실상 무시한다** — 이건 알려진 렌더링 특성이다. 독립된 테스트 페이지(3D 컨텍스트 없음)에서는 정확히 같은 CSS가 정상 작동했지만, 실제 `.knight-figure`(마우스로 기울이는 3D 틸트 효과가 있는 요소) 안에 넣으면 마스크가 적용되지 않았다 — 이게 v6.1이 아무 효과가 없었던 진짜 이유다. 이미지 자체가 알파 채널 없는 JPEG라는 원인 진단(v6.1)은 맞았지만, 그걸 고치는 방법(mask-image)이 이 3D 컨텍스트와 맞지 않았다.

### 조치 내용 — mask-image 대신 clip-path(ellipse) 채택
```css
.portrait-clip{
  position:relative; z-index:3; width:100%; height:100%;
  clip-path: ellipse(50% 45% at 50% 45%);
  filter:drop-shadow(0 18px 30px rgba(0,0,0,.55));
}
.portrait-clip img.hero-portrait{
  width:100%; height:100%; object-fit:cover; display:block;
}
```
`clip-path`는 마스크와 달리 3D 컨텍스트 안에서도 정상 렌더링됨을 별도 격리 테스트로 재확인했다. 소프트 페이드 대신 또렷한 타원 메달리온 형태가 되는데, 이건 기존 `.portrait-frame-ring`(금속 테두리 링)과 오히려 더 잘 어울린다.

### 검증 (이번엔 3중으로 확인)
1. `#knightStage` 요소만 격리 스크린샷 — 정지 상태에서 사각형 완전히 사라짐, 깨끗한 타원 메달리온 확인.
2. 마우스 틸트(rotateY/rotateX) 적용 상태에서도 동일하게 스크린샷 — 3D 회전 중에도 클립이 유지됨을 확인(이 부분이 v6.1이 놓쳤던 상호작용 상태).
3. Dio님이 보내주신 원본 스크린샷과 정확히 같은 프레임(모바일 폰 프레임 전체, 상태바 포함)으로 재현해 나란히 비교 — 사각형 잔상 없음.
파일은 Dio님 PC(`Desktop\VIBE CODING\Projects\WordCraft\UIUX_MVP_목업\wordcraft_uiux_mvp_v6.html`)에 재전달 후 크기 대조(1,743,394 bytes, 컨테이너 원본과 정확히 일치)로 전송 무결성 확인 완료.
